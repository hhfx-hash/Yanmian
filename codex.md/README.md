## 工作说明

1. 先判断当前任务属于哪个开发阶段；一次只推进一个阶段。
2. 开始工作时运行每日日志脚本，结束前填写完成事项、验证结果、风险和待办。
3. 先分析问题的根因和主流程，再决定修改；不使用静默兜底掩盖错误。
4. 优先复用成熟开源方案；新增依赖前记录选择理由、版本和许可。
5. 需求、接口、数据结构或视觉规则有变化时，先更新 `docs/` 对应文件并写入当日日志。
6. 未达到当前阶段退出条件时，不扩展后续阶段功能。
7. 所有敏感配置通过环境变量或部署密钥注入，禁止提交到代码和日志。
8. 开发完成后按 `docs/05-验收标准.md` 验证，并记录实际结果。
