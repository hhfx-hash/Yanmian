# 技术与计数规范

## 1. 选型原则

- 优先采用 GitHub、npm 或成熟生态中的稳定开源方案，避免重复实现认证、表单校验、邮件发送和数据库迁移。
- 先确定技术栈和版本，再创建应用代码；技术选型记录在 `06-风险与决策记录.md`。
- 所有依赖固定版本并记录安装来源。

## 2. 数据命名

- 数据库表和字段使用 `snake_case`。
- API 路径使用小写短横线。
- 前端组件和页面使用 `PascalCase`，变量和函数使用 `camelCase`。
- 时间统一保存 UTC，展示时转换为用户所在时区；同时保存明确的 ISO 8601 时间。

## 3. 计时定义

- `started_at`：用户点击开始并成功创建训练记录的时间。
- `ended_at`：用户结束训练或倒计时结束后确认结束的时间。
- `duration_seconds`：由开始和结束时间计算得到，服务端校验，不接受前端单独提交的结果。
- 暂停时不增加有效训练时长；暂停次数和暂停总秒数可作为扩展字段。
- 倒计时显示由前端根据服务端开始时间和模式计算，刷新页面后可恢复。

## 4. 题目抽取

- 抽取条件必须包含面试类型和题库来源。
- 公共题库只包含审核通过且未删除的题目。
- 私有题库只包含当前用户创建且未删除的题目。
- 随机抽题应使用数据库或成熟库提供的随机能力；不要将全量题库无界加载到浏览器。
- 无可用题目时返回可识别错误码和中文提示，禁止静默兜底。

## 5. 安全和数据约束

- 邮箱在账户系统中大小写归一化后唯一。
- 验证令牌、重置令牌只保存哈希值，使用后立即失效并设置过期时间。
- 密码不记录日志、不出现在错误信息中。
- 管理员接口和普通用户接口分离权限校验。
- 公共题目审核状态使用明确枚举：`pending`、`approved`、`rejected`。
- 删除优先使用软删除，避免训练历史失去关联；是否物理清理必须单独记录决策。

## 原型 v0.2 计时与数据口径

- 整场模式换题持续计时，答案阅读包含在整场时间内；单题模式完成回答后停止本题计时，下一题重新计时。
- 暂停不累计有效时长；重置倒计时不清零历史有效时长。
- 开始/结束保存 ISO 8601 UTC；有效时长按活动计时区间累计，不能仅以结束减开始代替。正式版由服务端校验区间。
- 到时只提示，不自动展示答案；答案需点击答题完成。
- 一次结束并保存的训练计为一次，抽取题数与回答题数分别记录；同场不重复抽已见题，题尽时提示。
- 原型代码使用 camelCase，正式数据库采用既定 snake_case；映射在后端阶段明确。
